# Музична фонотека

Лабораторна робота № 2 з курсу «Кросплатформні засоби програмування»:
«Класи, record і інкапсуляція в Java-проєкті». Варіант 13, предметна область «Музична фонотека».

## Призначення

Консольна програма читає записи про музичні треки з `data/input.csv` (або з файла,
указаного через `--input`), перетворює кожен коректний рядок на об'єкт `Track`,
обчислює чотири показники та виводить звіт у консоль і в файл `out/report.txt`
(або у файл, указаний через `--output`).

Показники:

1. кількість коректних записів;
2. сумарна тривалість, с;
3. середня тривалість треку, с;
4. найдовший трек (тривалість, виконавець і назва).

## Що змінилось порівняно з лабораторною роботою № 1

Зовнішня поведінка програми не змінилась: той самий формат входу, ті самі показники,
той самий текст звіту й повідомлень про помилки. Змінилась внутрішня модель даних.

| Було (ЛР № 1) | Стало (ЛР № 2) |
|---|---|
| запис — рядок, поля за індексами `fields[i]` | запис — об'єкт класу `Track` |
| перевірки в циклі методу `analyze` | перевірка інваріантів у конструкторі `Track` |
| розбір рядка в `analyze` | статичний фабричний метод `Track.fromCsv` |
| підсумки у вкладеному record `Main.Result` | окремий record `TrackSummary` |
| паралельні змінні `count`, `total`, `longest` | список `List<Track>` і обчислення над об'єктами |

## Вимоги

- JDK 21;
- Git;
- Maven встановлювати не потрібно: проєкт містить Maven Wrapper (`mvnw`, `mvnw.cmd`).

## Формат входу

Файл у кодуванні UTF-8, один запис в одному рядку, поля розділені крапкою з комою `;`:

```text
artist;title;album;durationSec;genre
```

## Клас Track і правила валідації

`Track` — незмінний клас: усі поля `private final`, сеттерів немає, клас `final`.
Об'єкт створюється лише через конструктор або `Track.fromCsv`, тому некоректний
запис не може потрапити до списку й не впливає на показники.

| Поле | Тип | Правило | Повідомлення про помилку |
|---|---|---|---|
| `artist` | текст | не `null`, не порожнє | `порожнє обов'язкове поле` |
| `title` | текст | не `null`, не порожнє | `порожнє обов'язкове поле` |
| `album` | текст | не `null`, не порожнє | `порожнє обов'язкове поле` |
| `genre` | текст | не `null`, не порожнє | `порожнє обов'язкове поле` |
| `durationSec` | ціле | число, більше нуля | `тривалість не є цілим числом`, `тривалість має бути додатною` |
| рядок | — | рівно 5 полів | `очікується 5 полів, знайдено N` |
| рядок | — | не порожній | `порожній рядок` |

Таблиця варіанта в методичці вказує «тривалість >= 0», але в ЛР № 1 нульова
тривалість відхилялась (трек без тривалості не має предметного змісту). Щоб зберегти
сумісність із попередньою роботою, правило залишено `> 0`.

`TrackSummary` — record із підсумковими показниками. Його компактний конструктор
відхиляє від'ємні значення, `NaN` та `null`.

## Збірка і запуск

Windows:

```text
mvnw.cmd clean verify
mvnw.cmd package
java -jar target/lab01-1.0.0.jar
```

macOS та Ubuntu: замість `mvnw.cmd` використовуйте `./mvnw`.

| Команда | Що виконується |
|---|---|
| `mvnw.cmd compile` | компіляція |
| `mvnw.cmd test` | компіляція і тести JUnit 5 |
| `mvnw.cmd verify` | компіляція, тести, статичний аналіз SpotBugs |
| `mvnw.cmd package` | усе перелічене та створення виконуваного JAR у `target/` |

Параметри програми:

```text
java -jar target/lab01-1.0.0.jar --help
java -jar target/lab01-1.0.0.jar --input data/input.csv --output out/report.txt
```

Запускайте програму з кореня проєкту, бо шляхи за замовчуванням відносні.

## Структура проєкту

```text
├── README.md
├── REPORT.md
├── pom.xml
├── mvnw, mvnw.cmd, .mvn/        Maven Wrapper
├── data/input.csv               приклад вхідних даних
├── ai/                          ролі ШІ-помічників
└── src/
    ├── main/java/ua/lpnu/kzp/
    │   ├── Main.java            аргументи, analyze, format
    │   ├── Track.java           клас-сутність: інваріанти, fromCsv, toString
    │   ├── TrackSummary.java    record із підсумковими показниками
    │   └── FileReport.java      читання й запис файлів у UTF-8
    └── test/java/ua/lpnu/kzp/
        ├── MainTest.java        тести analyze і format (перенесені з ЛР № 1)
        ├── TrackTest.java       тести Track, fromCsv і TrackSummary
        └── FileReportTest.java  тест запису й читання файла
```

## Тести

```text
mvnw.cmd test
```

Усього 26 тестів: 10 перенесено з лабораторної роботи № 1 (у `MainTest` змінено лише
тип `Main.Result` на `TrackSummary`, перевірки не змінювались) і 16 нових у `TrackTest`.
Вони охоплюють коректні, граничні й хибні значення конструктора та `fromCsv`,
`toString` і record.
